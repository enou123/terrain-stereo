# 喜界島のGMRT狭域・元資料調査

アプリの描画や公開水深データを変更せず、公式GridServerの取得結果を調べる。

## 取得計画

- 範囲：東経129.78〜130.14度、北緯28.18〜28.46度。喜界島全体と周囲の海底斜面（約35×31km）。鬼界カルデラとは別地点。
- `mresolution=500,250,100` の各指定で `topo` と `topo-mask` を取得。合計6リクエスト、逐次実行、待ち時間あり、自動再試行なし。
- 実際のGeoTIFFの座標系・境界・画素中心・格子間隔・欠測値を確認。指定値と返却格子間隔は区別する。
- 1ファイル12MiB、1グリッド90万セル、ジョブ15分の上限。既存14グリッドは再取得しない。
- 公式仕様・利用条件ページも取得し、日時・応答・SHA-256を記録する。

## 比較と解釈

現在、喜界島では最小包含領域の `okinawa-islands`（約877m）を使用する。保存済みデータのSHA-256を検証して比較基準にする。

新しい各グリッドの画素中心へ既存データを双線形補間し、海域のみの差分（RMSE、中央値、95%点、最大値）を計算。寄与マスクあり／なしを分け、100m対250m・500mも比較する。欠測を埋めない。取得範囲の外側の余白を統計に含めない。

`topo-mask` の有限値セルを高解像度資料寄与の候補として集計し、元のマスクと公式仕様を保存して解釈を確認する。元のGeoTIFFも加工せず保存する。寄与マスクは測深精度・測定日・個別の測量方法を示すものではない。

細かな返却格子や既存データとの差分だけでは、実測資料の追加を証明できない。差分には再サンプリング、既存1m整数化による最大約0.5mの丸め、版の違いが含まれる。寄与マスクで実測由来の追加を確認できない場合、高精細データのアプリ追加は行わない。

## 実行と保存

Actionsの **Investigate Kikai GMRT source resolution** が、この調査用スクリプト／ワークフローのmainへの更新時に実行される。手動実行も可能。アプリへの書き込み権限は与えず、`contents: read` のみ。

成果物 **kikai-gmrt-source-investigation** に `report.json`、6つの元GeoTIFF、公式ページを保存する（30日）。大きな元GeoTIFFは公開リポジトリやPagesには追加しない。成功判定は3解像度すべての取得・座標・値・マスク整合検証の成功であり、高精細な実測資料の存在は別に報告する。

計算テスト：`python tests/kikai-gmrt.test.py`。合成入力の単体テストであり、公式データ取得の成功とは区別する。

## 2026-10-11の実取得結果

[Actions実行38111615312](https://github.com/enou123/terrain-stereo/actions/runs/38111615312) は成功。手動操作は不要だった。公式GeoTIFF6ファイルと仕様・利用条件2ページはすべてHTTP 200。

| 指定間隔 | 実際の東西×南北間隔 | 返却グリッド | 海域の高解像度寄与 |
| --- | --- | --- | --- |
| 500m | 約53.91×53.92m | 658×583 | 0 / 358,338セル |
| 250m | 約53.91×53.92m | 658×583 | 0 / 358,338セル |
| 100m | 約53.91×53.92m | 658×583 | 0 / 358,338セル |

3つのtopoファイルのSHA-256は同一、3つのtopo-maskのSHA-256も同一。指定値どおりに3段階のデータが返されたわけではない。共通の返却範囲は東経129.7790218〜130.1410221、北緯28.1788019〜28.4612069。欠測1,316セルは主に返却画像外周で、欠測を水深0に置換していない。

公式仕様により `topo-mask` は海域の高解像度資料がある場所の標高値を残し、それ以外をNaNとする。今回の有限マスク17,186セルは陸上で、海域の有限マスクは全解像度で0。有限マスクの値はtopoと完全一致した。したがって、今回の範囲で**GMRTが高解像度資料寄与として識別する海底データは確認できなかった**。これは背景資料に実測値が一切含まれないこと、別機関にも詳細資料がないこと、取得範囲の外にも寄与がないことを意味しない。

### 既存約877mデータとの差

同じ画素位置で既存データを双線形補間した値に対し、海域差分のRMSEは約33.19m、絶対差中央値16.15m、95%点71.11m、最大224.02m、平均差−9.13m（新取得のほうが平均で深い）。取得水深は約0.01〜1,107.09m。

**今回の狭域データは既存877mグリッドの単純な双線形補間とは異なる**。ただし、この数値差だけでは細かな実測資料の追加を証明できない。背景グリッドの再サンプリングや広域データ取得時の情報の間引きなどが考えられ、原因の内訳は今回の取得結果だけでは確定しない。約54mの返却格子を「約54m精度の測深」として扱わない。

### 出典・容量・保管

- 応答ファイル名で **GMRT v4.5.0** を確認。今回取得したAPI説明ページには背景をGEBCO_08とする古い記述もあり、新取得ラスタの背景版番号をこのページだけで確定しない。既存の877m manifestにはGEBCO 2026と記録されている。
- 利用条件ページでCC BY 4.0、GMRTへのクレジット、Ryan et al. (2009), doi:10.1029/2008GC002332、およびデータdoi:10.1594/IEDA.100001を確認。
- 元TIFFは各1,536,382バイト、6つで9,218,292バイト（約8.79MiB）。1リクエスト0.8〜1.3秒。成果物ZIPは4,294,070バイト、SHA-256 `79b818ea8bd5942474848feeae4048b5425e5c118b886e825e424bfb6540e8f5`。
- ZIPと元TIFFは開発作業領域へ回収済み。数値・座標・取得URL・SHA-256・比較統計は[report.json](bathymetry/kikai-gmrt-investigation-report.json)としてリポジトリにも保存し、Actions成果物の期限に依存しない記録とした。元TIFFはPagesに追加していない。

### 判断

実取得には成功したが、高解像度測深資料の寄与は確認できなかった。依頼の方針に従い、喜界島用の高精細データはアプリへ追加せず、既存データ・描画・設定を維持する。背景データの間引きを減らす狭域取得の効果を、将来「実測精度向上とは別の改善」として比較する余地はある。今回そこまでのアプリ改修やブラウザ比較は実施しない。

調査用単体テスト3件、既存JavaScriptテスト15件が成功。調査コードは `6431d8c` でmainに反映済み。同コミットのPagesデプロイ `38111614865` も成功したが、アプリの機能・バージョンは変更していない。
