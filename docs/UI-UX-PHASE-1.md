# フェーズ1：UI/UXの基礎改善

## 既存コードの調査と設計（実装前）

0.5.1は`styles.css`の幅640px以下で縦配置、その他は3D＋設定の横配置。横画面のスマートフォンでは設定が250pxを占め、ビューの最低高さ720pxが画面を超える。設定を閉じる手段や3Dを画面いっぱいにする手段はない。操作エリア以外のスクロールは維持されている。

- PC：左右配置を維持、ビューの高さを画面に合わせる。設定を開閉し、3Dを広げる手段を追加。
- iPhone縦：ビュー＋下の設定。44px以上のボタン、スライダー操作領域、設定の開閉。
- iPhone横：幅だけでなく縦横比・高さで判定。ビューは全幅、設定は初期状態で閉じる。高さはブラウザの表示領域に合わせる。
- 共通：ビュー上部に地図への移動、設定開閉、拡大表示。拡大表示はFullscreen APIに依存せずCSSでブラウザ内を使う。動的ビューポート単位、safe-areaを考慮。拡大表示時は設定をスクロール可能な重ね表示にし、背景への操作・フォーカスを抑止。Escape・終了ボタンで戻る。
- 地点、視点、画質、立体視、高さを保持し、配置変更だけでDEMを再取得しない。設定DOMを複製せず、既存イベントの接続を維持する。

## 今回の対象と非対象

今回は上記の画面配置、操作導線、アクセシビリティのみ。方位、注視マーク、等高線、表面テクスチャ、航空写真・地質等のレイヤー、断面・計測、飛行、太陽、保存・共有、世界地形、PLATEAU、探索・学習モードは後続フェーズ。

## 後続の設計方針

既存の`elevation.js`（DEM取得）、`mesh.js`（地形生成）、`renderer.js`（描画）、`controls.js`（操作）、`map.js`（地図）、`app.js`（接続）を尊重する。今回のレイアウト制御は独立した`viewer-ui.js`に置く。

今後はDEM・画像テクスチャ・地質・都市3Dをデータ種別ごとの取得モジュールに分離し、取得条件・範囲・出典・欠損・キャンセル・キャッシュを各モジュールで管理する。重い機能のコードとデータは選択時に読み込む。今回、未使用の取得基盤や新たな外部依存は追加しない。
