# 日本周辺の海底地域カタログ（実データ取込前の設計）

## 現在の状態

- 既存の青ヶ島狭域・八丈島〜青ヶ島広域の実GMRTデータはそのまま利用します。
- `js/bathymetry-spots.js` に海底を観察する30地点の候補を独立データとして登録し、既存17名所と同じ検索・分類UIへ追加しています。
- `js/bathymetry-regions.js` は新しいデータ地域の索引です。データを取得・実検証するまでは、新地域のmanifest/binaryは置かず、公開済みの海底データとして扱いません。
- `.github/workflows/acquire-marine-data.yml` は手動実行専用です。公的なGMRT GridServerから指定した範囲だけを取得し、GeoTIFFを直接Pagesへ置かず、圧縮前の数値値・欠測mask・出典情報を持つ小さな配信用形式を生成します。

GitHub Actionsで実行する場合は、`Actions` → `Acquire Japanese GMRT marine grids` → `Run workflow` → `region_group: all` を選びます。Artifactsの`report.json`で各地域が成功し、返却された実格子間隔・範囲・容量・SHA-256を確認してから配信ファイルへ採用します。処理は各公式リクエスト間に待ち時間を設け、GeoTIFF・格子数・ファイル容量に上限を設けています。

## 読み込みとメモリ

現在の地形表示フットプリントが一つの地域内に収まる場合は、最小の包含グリッドだけを選びます。地域境界をまたぐ広域表示では、表示枠と交差するすべての地域を選びます。広域に適した低解像度グリッドと狭域の細かいグリッドが重なる場合、細かい格子を優先し、タイル端の2格子で滑らかに混ぜます。欠測は陸や水深に置き換えず、穴として保持します。

海底OFF中はmanifestも数値データも取得しません。ON時のみ必要な地域を読み、各manifestとbinaryのサイズ・形式・SHA-256を確認します。数値配列とmaskのLRUキャッシュ上限は合計8MiB、最大8地域です。1地域は900,000格子・2,000,000 bytes以下に制限します。

## 地点記述と解釈

海底スポットには推奨中心・縮尺・高さ倍率・水深色の上限・観察ポイントを持たせます。地形の説明では表示値から直接観察できる起伏と、外部の公的資料で確認すべき地質解釈を分けます。格子間隔は測深精度ではなく、基礎グリッドや寄与する測量データの品質は場所ごとに異なります。
