# 立体表示から読込範囲を変更（0.30.0）

## 操作

「範囲・遊覧」を開き、通常のドラッグ操作で視点を調整します。

- Shift＋ドラッグ／中ボタンドラッグ／2本指の平行移動 → **① この位置へ移す**。カメラの注視点の移動を東西・南北の距離に換算し、同じDEMズームで新しい中心の標高データを取得します。
- ホイール／ピンチ → **② ズームを範囲に反映**。読込中心を固定し、カメラ距離の比率から範囲を決めて標高を再取得します。未反映の平行移動は取り消します。
- **遊覧飛行**。従来の自動遊覧を維持。旧矢印・高度ボタンと手動飛行モードへの入口を削除しました。

操作だけでは再取得しません。地図から自由に場所を選ぶ操作も維持しています。①は未反映のズームを保持するので続けて②を使えます。読込後は新しい地形の中心へ注視点を戻し、向きと表示設定を保持します。地図・共有リンクの座標とズームも更新します。異なる範囲になった名所の解説は閉じ、おすすめ表示の説明と混同しないようにしています。

## 計算と制限

地形メッシュの正規化後の実幅と、DEMの384ピクセル四方の範囲から注視点の平行移動をMercator座標へ換算します。回転角によって移動方向が誤らないよう、画面のドラッグ量ではなく3D注視点を使います。

範囲のズームは既存の地図・DEM・共有リンクと同じ整数6〜14です。カメラ距離の比から `現在のzoom + log2(基準距離 / 現在距離)` を求め、最寄りの段階に合わせます。隣の段階は約半分／2倍です。小さいズーム差ではボタンを無効にし、段階と予想範囲を表示します。高さ倍率は縮尺に影響しません。

日本周辺の対応範囲外の移動は拒否します。新しい地形でカメラが最高標高より低くならないよう、注視点の高さを補正します。DEM取得失敗時は元のデータ・視点を維持し、再試行を案内します。テクスチャ取得失敗の扱いは既存の標高色への復帰と通知を再利用します。

機能紹介ツアーの開始時は範囲変更の基準視点も保存し、終了時に戻します。名所のおすすめ視点を適用した場合はその視点を新しい基準とし、初期オフセットを利用者の移動と誤認しません。

## 検証

- `npm test`：既存テストと新しい座標換算・距離比・境界のテスト。
- `python tests/view-range.browser.py`：国土地理院の実DEM（取得済み実タイルのキャッシュを含む）を使った中心移動、範囲変更、移動とズームの独立反映、取得失敗時の復帰、遊覧飛行、WebGLエラー確認。
- `python tests/ui.browser.py`：共有、PNG、等高線、立体視、表示切替など既存UI。地質画像はテスト用画像であり、産総研の実データの成功確認には含めません。
- `TERRAIN_TOUR_VIEWPORTS=1440x900 python tests/tour.browser.py`：既存10場面の実行・終了後の復元。地質図はテスト用画像。

範囲変更の確認サイズは1440×900・390×844・844×390。Chromium＋SwiftShaderのWebGLです。iPhone実機Safariでの確認ではありません。範囲変更テストでは背景地図に取得済みタイルを使用し、未取得の背景地図タイルは404として処理します。DEMを架空データへ置換していません。
