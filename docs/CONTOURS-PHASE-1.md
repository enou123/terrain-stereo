# 等高線：第1段階（0.8.0）

## 対象と配置

既存の設定欄に44px以上のタップ領域を持つチェックボックスを1つ追加する。初期OFF、100 m間隔を説明。PCの設定開閉、iPhone相当の縦配置・横画面優先の3D領域を維持する。通常3D・平行法・交差法・赤シアンすべて同じ地形表面に描画する。線間隔選択、ラベル、テクスチャ、断面等は追加しない。

## 既存構造への影響

メッシュには元の標高（m）を頂点属性として追加する。位置に適用する高さ強調・基準標高の除去・表示用の縮尺とは分離する。従来どおりNaNを含む三角形を除外するため、線だけが海・欠損部分に浮かぶことはない。

同じフラグメントシェーダー内で三角形の標高を補間し、100 mの倍数を線にする。独立した線メッシュ・描画パス・データ取得は増やさない。z-fightingを避け、左右のカメラにも自動的に追従する。赤シアンでは線も既存の白黒変換と色チャンネル分離を通る。

画面内の標高変化量に基づいて線幅を調整し、DPR2でも約1 CSS pxの線を保つ。平坦面の全面着色と、密集線が面全体を暗くする現象を抑える。線を分離できない縮小状態では薄くする。細部の正確さは読み込んだDEMの画質・補完データに依存する。

切替はuniformの更新と既存のrequestDrawだけで行う。取得・メッシュ生成は呼ばない。Rendererの設定とチェックボックスを保持し、地点・画質変更や高さ強調でsetMeshを呼んでも状態をリセットしない。

WebGL1のOES_standard_derivatives拡張を確認し、非対応時は従来の描画シェーダーを使用する。等高線だけを無効にしてUIに説明し、3D全体の初期化失敗にはしない。

## 検証方針

元標高の保持・NaN三角形除外はNodeテスト。既知の傾斜標高・平坦面・欠損穴・拡張非対応はChromiumの実WebGL画素で検証。実DEMの8画面サイズでON/OFFの画素復帰・追加通信なし・回転・各立体視・高さ・拡大・設定開閉・状態保持を確認する。沿岸部の3画面サイズでは高画質404補完と等高線の併用を確認。スクリーンショットを目視確認してから記録・コミットする。Safari実機と物理GPU性能は別途確認が必要。
